def compute_composite(judge_results: dict[str, dict]) -> float:
    """Weighted composite score 0–100 from judge results.

    Each judge's 1–5 score is normalised to 0–100 before weighting.
    Missing judges contribute 0 to their weighted slot.
    """
    total = 0.0
    for name, weight in JUDGE_WEIGHTS.items():
        jr = judge_results.get(name, {})
        score = jr.get("score", 0)          # 1–5 or 0 if missing
        normalised = max(0.0, (score - 1) / 4.0) * 100   # 1→0, 5→100

This is a really sharp diagnostic framework. You're describing a 4-state taxonomy that turns a binary "fact missing" signal into an actionable root cause. Let me map it out precisely:

The 4 states when a key fact is absent from the answer:

State Fact in retrieved 1000 words Right article searched Fact in answer Diagnosis Root cause
A ✅ ✅ ❌ Extraction failure Model had the content, didn't use it — prompt grounding discipline
B ❌ ✅ ❌ Cutoff limitation Correct search, fact lives deeper in the article — system constraint, not prompt failure
C ❌ ❌ ❌ Retrieval failure Wrong article searched — query formulation problem
D ❌ any ✅ Grounding failure Fact in answer but NOT in retrieved content — used training knowledge

State D is the most serious — that's hallucination. State B is not a prompt failure at all and shouldn't penalise the prompt score. The current key_facts_present check conflates all four into one binary signal, which makes it impossible to know what to fix.

On the full-article fetch for State B: You're right that confirming "fact is in the article but beyond 1000 words" requires fetching the full article. There's a tradeoff:
